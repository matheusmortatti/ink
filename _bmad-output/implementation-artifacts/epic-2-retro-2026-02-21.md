## Challenges and Growth Areas

### Glamour Output Assumptions Caused Cursor Mapping Edge Cases
The most technically complex story (2.5) was written against assumed Glamour output rather than verified Glamour output. This led to:
- A triple-asterisk (`***bold italic***`) delimiter bug
- A table separator row (`| --- | --- |`) not being skipped
- A double-escaped backslash (`\\*`) classification error

All three were caught in code review, not during development or automated testing.

**Root cause:** We documented expected Glamour transforms in a reference table but treated Glamour as a black box. Tests verified *internal consistency* (round-trip fidelity) but not *user-observable behavior* (where the cursor actually lands on screen).

### ANSI Complexity Was an Underestimated Cross-Cutting Concern
ANSI escape sequences affected three consecutive stories:
- Story 2.3: `wrapLine()` needed to become ANSI-aware
- Story 2.4: Test environment produced no ANSI codes (non-TTY)
- Story 2.5: Rendered positions required ANSI stripping to get visual character counts

The same underlying issue surfaced three times. Should have been addressed as an architectural concern after Story 2.3.

### Manual Testing Filled a Gap Automated Tests Didn't
Matheusmortatti conducted exploratory manual testing — navigating through documents, entering/exiting insert mode, verifying motions. This was valuable and caught real issues. However:
- It was ad hoc, not structured
- Coverage was unknown (what scenarios were tested vs. missed?)
- Code reviewer suggestions to "manually test X" resulted in manual checks, not new automated tests

### Bidirectional Consistency ≠ User-Observable Accuracy
The cursor mapping test strategy verified `MapRawToRendered(MapRenderedToRaw(pos)) == pos` — mathematically consistent — but didn't verify that the initial rendered position corresponded to what a user sees on screen. These are different properties.

---

## Key Insights

1. **Performance discipline pays.** Benchmark early, benchmark concretely. The headroom earned compounds across every future epic.
2. **External library output must be treated as discovered, not assumed.** Golden file tests — capture actual Glamour output as fixtures, test against those, not against assumptions.
3. **Exploratory testing by the project lead is irreplaceable — but needs a checklist.** Ad hoc is better than nothing; structured is better than ad hoc.
4. **Forward-thinking investments make the next epic easier before it starts.** DimStyle and ANSI-aware wrapLine are already paying forward into Epic 3.
5. **"Manually test X" from a code reviewer is a signal to write a test, not just check once.**
